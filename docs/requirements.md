# AI 기반 경험관리 서비스 — 요구사항 정리 (v0.1)

> 가칭 **Rewrite** · "문서를 쓰기 전에, 경험부터 발굴한다"

## 1. 한 줄 정의

사용자가 **스스로 떠올리지 못한 경험을 AI가 먼저 질문해 끌어내고**, 그 과정·의사결정·성장을 **구조화된 경험 카드**로 축적해 **직무 역량 키워드**와 연결해 주는 경험관리 서비스.

## 2. 문제 정의 (왜 만드는가)

| # | 사용자가 겪는 문제 | 서비스의 대응 |
|---|---|---|
| P1 | 평범한 활동은 "경험"이 아니라고 생각한다 | 일상·알바·수업까지 "작은 경험" 질문으로 가치를 재발견 |
| P2 | 어떤 경험을 이야기할지 떠올리지 못한다 | 기억 회상용 질문(상황·장소·사람·감정 트리거)을 먼저 던짐 |
| P3 | 경험 속 의미 있는 행동을 집어내기 어렵다 | 꼬리질문으로 "내가 한 행동/판단"을 분리해 STAR로 정리 |
| P4 | 경험이 어떤 직무 역량을 보여주는지 모른다 | 역량 키워드 자동 매칭 + 목표 직무 연관도 표시 |
| P5 | 백지에서 무엇부터 써야 할지 결정하기 어렵다 | 빈 입력창 대신 **질문이 먼저 오는** UX |
| P6 | 결과물(GitHub 등)은 남아도 협업·문제해결·의사결정 과정은 사라진다 | 프로젝트마다 그 프로젝트에 대해 AI와 나눈 대화(경험)를 모아 과정 기록 |
| P7 | 과거 경험은 시간이 지나 흐릿해진다 | 지금 하는 일을 **실시간에 가깝게** 기록하는 주기 질문 |

## 3. 타깃 사용자

1. **신입 취업 준비생** — 경험이 부족하거나 평범하다고 느끼고, 자소서·면접에 쓸 경험을 찾기 어려움 (핵심 타깃)
2. **직무 전환 준비생** — 기존 경험을 새 직무 역량으로 재해석해야 함
3. **주니어 이직 준비생** — 자신의 기여·성과를 정리해야 함

## 4. 차별점

- **기존 취업 서비스**(채용정보·자소서·면접 준비) → 우리는 문서 작성 *이전* 단계인 **경험 발굴·지속 기록·관리**에 집중
- **"입력하면 분석"** 서비스 → 우리는 **떠올리는 단계부터** 돕는다
- **노션/메모앱** → ① 서비스가 **먼저 질문을 던지고 이끈다** ② 직무 역량·커리어에 바로 쓰는 **구조화된 형식**으로 정리 ③ 이 흐름에 최적화된 UI/UX

## 5. 하나의 흐름: 기록 → 경험 위키 → 꺼내 쓰기

안드레 카파시의 **LLM 위키**처럼, 사용자는 원문 기록만 넣고 AI가 그 기록을 엮어 **개인 경험 위키**를 계속 정리·유지한다. 이력서·자소서·면접은 이 위키를 근거로 꺼내 쓰는 결과물이다.

```
① 대화 기록 (원문, 채팅방)          ② 경험 위키 (AI가 정리·유지)              ③ 꺼내 쓰기 (위키를 인용)
 오늘의 질문 ─┐                     경험 카드 (STAR·역량·담긴 경험)          마스터 이력서
              │                     프로젝트 페이지 (경험·대화·코드)  ──▶    자소서 · 역량 맵
 ＋기록하기 ──┼─ AI와 대화 ─▶ 경험 ─ 제안·확인 ─▶ 변경 기록                   면접 준비
 프로젝트 이야기 ┤ (끝낸 대화 하나 = 경험 하나)
 코드 질문 ───┘      └─ 카드에 담거나, 새 카드를 만들거나, 카드 없이 경험으로만 저장 → 나중에 여러 경험을 모아 카드로
```

- **원문 = 대화 기록(채팅방)**: AI와 나눈 모든 대화(AI 질문과 사용자의 말)를 메신저처럼 그대로 보관한다. **사용자가 AI와 끝낸 대화는 모두 경험이 된다** — "확정 전" 상태는 없다. 경험 카드의 '담긴 경험'과 프로젝트 타임라인은 이 대화 원문으로 이어진다. 아직 어떤 카드에도 담기지 않은 경험은 대화방에서 [카드에 담기]로 언제든 카드에 넣을 수 있다.
- **경험 카드 = 경험을 모은 것**: 흩어진 경험 여러 개를 하나의 이야기(STAR·역량)로 모아 면접·이력서·자소서에 쓰기 좋게 만든 것. 만드는 길은 둘이다: ① 질문함의 편집 모드에서 경험 여러 개를 골라 [선택한 경험으로 카드 만들기], 또는 카드 화면의 [＋ 경험 더 담기]로 보태기 ② '경험 하나 끝까지 정리하기'(AI와 길게 대화)로 긴 대화 하나에서 카드 하나를 바로 만들기. 경험 하나가 여러 카드에 담길 수도 있다.
- **가볍게든 깊게든 같은 위키**: 한 줄 답변과 레포 코드 분석은 입력의 깊이만 다를 뿐, 같은 경험 카드를 채운다. 별도의 "분석 공간"을 두지 않는다.
- **모든 입력은 입구 하나(ingest)를 지난다**: 비슷한 경험 카드가 있으면 그 카드의 알맞은 칸(상황·과제·행동·결과·배운 점)에 보태고, 없으면 새 경험 카드를 만든다.
- **AI와 대화하며 적고, 반영은 사용자가 정한다**: 오늘의 질문·＋기록하기·프로젝트 이야기는 모두 같은 **기록 대화**에서 쓴다. AI가 질문하고 → 사용자가 답하고 → (필요하면 꼬리질문 1번) → 대화는 경험으로 저장되고, AI가 **"「X」 카드의 결과 칸에 이런 문장으로 담을게요"** 하고 제안한다. 사용자는 대상 카드·칸·문장을 고르거나 말로 고쳐서("새 카드로 만들어 줘", "결과 칸에", "카페 알바 카드에") 정한다. **새 경험 카드 만들기**, 또는 **카드 없이 경험으로만 저장**도 고를 수 있다(근황처럼 이야기가 없는 답이면 AI가 먼저 경험으로만 저장을 제안). 별도의 "타임라인에만 기록"은 없다. 원문 답변은 고친 문장과 별개로 출처에 그대로 남는다.
- **반영 결과는 바로 보여 준다**: 정한 뒤에는 "위키에 반영했어요" 카드로 실제로 바뀐 내용을 보여 주고, 되돌리기를 제공한다.
- **직접 수정에는 AI가 개입하지 않는다**: 경험 카드의 ✎ 수정은 사용자가 쓴 그대로 저장하고, 변경 기록에만 남긴다.
- **처음 쓰는 사람에게 단순하게 — 없앤 개념**: ~~위키 점검(lint)~~(빈 곳 목록·사이드바 배지·하루 한 번 자동 질문), ~~경험 카드 상태 `작성중`/`완성`~~, ~~완성도(%)~~는 두지 않는다. 경험 카드는 "다 채웠는지"를 따지지 않고, 경험을 모을수록 단단해진다. 코드 분석 질문은 레포를 분석할 때(ingestCode) 오늘의 질문으로 들어온다.
- **용어**: 경험(=AI와 끝낸 대화 하나, 원자 단위) · 경험 카드(=경험 여러 개를 모아 STAR로 정리한 것, 면접·이력서·자소서에 꺼내 쓰는 단위) · 기록(=원문) · 위키에 반영(=정리) · 경험 위키(=보관함) · 프로젝트(=경험을 묶는 허브 페이지) · AI와 대화하며 기록. ('경험 후보'라는 개념은 없앴다 — 끝낸 대화는 모두 경험이다.)
- **경험 그래프**(메뉴: 경험 위키 위): 경험·경험 카드·역량·프로젝트·코드 분석을 노드로, 그 사이의 연결(경험이 담긴 카드, 카드의 역량, 프로젝트, 근거 코드)을 선으로 그린 지도. 끌어서 옮기고 확대·축소할 수 있고, 필터를 켜면 조건에 맞지 않는 노드는 흐리게(채도를 낮춰) 보여 줘서 어떤 경험이 어디에 쓰였는지, 어느 역량이 비어 있는지 한눈에 본다.

### 5.1 입력 경로 (모두 같은 위키로)

| 입력 | 언제 | 위키에 반영되는 방식 |
|---|---|---|
| **오늘의 질문** | 설정한 주기에 질문 1개 도착 | 특정 경험을 깊이 파는 질문이면 그 경험의 해당 칸을 채움. 회상 질문이면 비슷한 경험을 찾아 보태거나 새 경험 생성 |
| **프로젝트 이야기** | 프로젝트 페이지에서 원할 때 (주기적으로 묻지 않는다) | AI가 질문 하나를 건네고, 끝낸 대화는 그 프로젝트의 경험이 되어 타임라인에 쌓인다. 결정·문제·협업·배움 이야기는 그 프로젝트의 관련 경험 카드에 담을 수 있다(없으면 새 카드) |
| **AI와 대화하며 기록** | 시간을 내서 정리할 때 | 꼬리질문으로 STAR를 채움. 기존 경험과 같은 이야기면 거기에 반영할지 묻는다. 프로젝트의 코드 분석 결과와 연결할 수 있다 |
| **GitHub 코드 분석** | 프로젝트에 레포 연결 시 | 같은 기술 이야기를 하는 경험에 코드 근거로 붙고, 이야기가 없는 발견은 "왜 이렇게 만들었나요?" 질문으로 오늘의 질문에 도착 → 답하면 코드 근거가 붙은 경험이 생긴다 |
| **＋ 기록하기 (한 줄)** | 언제든, 상단 버튼 하나 | 한 줄을 남기면 위와 같이 매칭·반영 |

## 6. 핵심 객체: 경험 카드

| 필드 | 설명 |
|---|---|
| 제목 / 유형 | 프로젝트, 동아리, 아르바이트, 수업·과제, 대외활동, 일상 등 |
| 기간 | 시작~종료 (종료가 비면 진행중으로 표시) |
| 나온 프로젝트 | (선택) 이 카드가 나온 프로젝트와 근거로 고른 프로젝트 기록(로그) |
| 역할 / 한 줄 요약 | 내 포지션, 경험 요약 |
| **STAR 정리** | 상황(S) · 과제(T) · 행동(A) · 결과(R) |
| 배운 점 / 성장 | 경험을 통해 달라진 점 |
| **역량 키워드** | `#협업` `#문제해결` 등 1개 이상, AI 추천 + 사용자 수정 |
| 연관 직무 | 목표 직무와의 연결 |
| 출처 | 이 경험을 만든 모든 기록 — 질문 답변·AI 대화·프로젝트 기록(`sourceLogIds`)·코드 분석 발견(`codeRefs`) |
| 변경 기록 | 각 기록이 이 경험의 어느 칸을 바꿨는지 (`wikiLog`) |

### 6.1 프로젝트와 경험 카드의 관계 (1 : N)
- **프로젝트**는 그 프로젝트에 대한 경험(AI와 끝낸 대화)을 모으는 그릇이다 (제목·역할·기간·상태 `진행중`/`완료`·결과물 링크·로그). 프로젝트 타임라인 = 그 프로젝트에 관한 경험을 날짜순으로 보여 준 것이고, 로그 유형(의사결정·이슈·협업·배움·마일스톤)은 타임라인 항목에 붙는 선택적인 작은 태그다.
- **경험 카드**는 에피소드 단위다. 한 프로젝트에서 "검색 API 성능 개선(#문제해결)", "API 명세 합의(#협업)"처럼 여러 장이 나온다. 자소서·면접에서는 에피소드 단위로 꺼내 쓰기 때문이다.
- 카드는 `projectId`로 프로젝트를, `sourceLogIds`로 근거 로그를 가리킨다. 프로젝트 없이 단독으로 존재하는 카드도 있다 (아르바이트, 동아리 등).
- 로그 하나는 여러 카드의 근거가 될 수 있고, 카드를 지워도 로그는 남는다.
- 프로젝트 대상 질문(오늘의 질문)에 답하면 원문은 그 프로젝트의 로그로 쌓이고, 같은 답이 관련 경험에 반영된다(마일스톤만 있는 기록은 타임라인에만).
- **주기적인 프로젝트 질문은 없다**: 프로젝트마다 정해진 주기로 질문을 보내거나 "오늘 기록할 차례" 같은 알림을 띄우지 않는다. 프로젝트 페이지의 [이 프로젝트 이야기 남기기]에서 원할 때 AI와 대화하면 되고, AI는 가장 덜 기록된 유형의 질문부터 건넨다. ＋기록하기·AI와 대화에서 프로젝트를 고른 경험도 같은 프로젝트에 모인다.

### 6.2 마스터 이력서
- 자소서는 기업마다 달라지지만 이력서는 대부분 공통이다. 그래서 이력서는 기업별이 아니라 **하나의 마스터 이력서**로 관리한다.
- 마스터 이력서는 이력서에 쓸 수 있는 재료가 계속 쌓이는 **풀**이다. 프로젝트 성과 한 줄, 경험 카드 요약, 기술 스택, 경력·활동·학력·수상이 여기에 모인다. 사용자는 그중 마음에 드는 것만 골라 **현재 이력서**에 넣는다(포함/제외). 뺀 항목도 지우지 않고 풀에 남겨 둔다.
- 이력서를 업그레이드하는 과정(새 성과 추가 → 더 나은 것으로 교체 → 오래된 것 빼기)은 포함 여부 토글, 문장 다듬기, 순서 바꾸기, **버전 저장·비교·되돌리기**로 지원한다.
- 재료 출처: ① 프로젝트에 연결한 **GitHub 레포 코드 분석** 결과, ② 경험이 담긴 경험 카드, ③ 직접 작성. 각 한 줄은 출처를 기억한다(코드 분석은 파일·줄 번호 근거 포함).
- 포트폴리오는 이력서를 더 자세히 풀어 쓴 것으로 보고, 마스터 이력서 이후에 다룬다.

### 6.3 GitHub 레포 코드 분석
- 질문·답변만으로는 이력서에 쓸 **기술적 성과**(성능 개선, 인증 구조, 동시성 제어, CI/CD, 테스트 등)를 끌어내기 어렵다. 그래서 프로젝트에 GitHub 레포 주소를 연결하면 코드를 분석해 이력서에 쓸 만한 항목을 찾아 준다.
- 각 항목은 분류, 이력서용 한 줄, 왜 눈에 띄는지(면접 포인트), 기술 태그, **근거 코드(파일 경로·줄 범위·코드 조각·GitHub 링크)**로 구성된다. 코드만으로 알 수 없는 수치는 빈칸(○○%)으로 두고 사용자가 채운다.
- 사용자는 항목을 보고 문장을 고친 뒤 골라서 마스터 이력서에 담거나 제외한다. 담은 항목은 해당 프로젝트의 이력서 항목 아래 한 줄로 들어가고, 태그는 기술 스택 풀에 쌓인다.
- 프로토타입: 공개 레포는 GitHub REST API로 실제 파일을 읽고, 분석은 규칙 기반(모의 AI)으로 한다. 요청 한도(시간당 60회)를 넘거나 레포가 없으면 예시 데이터로 대신한다.

## 7. 기능 요구사항

### 7.1 MVP
- **F1 온보딩**: 사용자 유형(신입/전환/이직), 목표 직무, 질문 알림 주기·시간 설정, (선택) GitHub 레포 연결, 첫 기록은 한 줄로 가볍게
- **F2 홈**: 한 칸에 오늘의 질문, 지원 기업(마감 임박 3곳), 답변 캘린더. 위키 변경 기록은 경험 위키·경험 카드에서 본다
- **F3 AI와 대화하며 기록**: AI 꼬리질문, 탈출구 버튼, 실시간 STAR 채움, 프로젝트·코드 분석 연결, 기존 경험과 같은 이야기면 반영 대상 확인, 종료 시 위키 반영 결과. 상단 "＋ 기록하기"·경험 카드에서 들어간다
- **F3.1 ＋ 기록하기**: 모든 화면 상단의 단일 입구. 한 줄 기록(바로 위키 반영) / AI와 대화 / GitHub 레포 분석 / 직접 작성
- **F4 오늘의 질문함**: 주기 질문 수신·답변·나중에 답하기(답하지 못한 질문으로 옮겨 두고 언제든 답함), 답변 전 "어디에 반영되는지" 안내, 답변 후 위키 반영 결과(되돌리기·옮기기), 연속 기록(스트릭), 편집 모드에서 경험 여러 개를 골라 경험 카드 만들기. 질문 출처: 회상 · 경험 깊이 파기 · 코드 분석
- **F5 프로젝트**: 경험을 묶는 허브 페이지. 이 프로젝트에 관한 경험(대화)을 날짜순 타임라인으로 모음, 프로젝트 이야기 남기기(타임라인에 기록 + 관련 경험 카드에 반영), 로그마다 반영된 경험 표시, 코드 분석 결과와 연결된 경험 표시, 이 프로젝트의 경험 목록
- **F6 경험 카드**: 상세 조회, 생성·수정, 키워드, **담긴 경험**(이 카드에 모은 대화 원문, 대화 보기 링크) + 코드 근거, **＋ 경험 더 담기**(아직 이 카드에 없는 경험 고르기, 같은 프로젝트 먼저), **변경 기록**, AI와 이어서 채우기
- **F6.1 경험 그래프**: 경험·경험 카드·역량·프로젝트·코드 분석 노드와 연결, 드래그·확대/축소, 필터(맞지 않는 노드는 채도를 낮춤)
- **F7 경험 위키**: 색인(프로젝트별/역량별/최근 순), 최근 변경, 검색·필터, 정렬(최근 수정순·경험 많은순·기간순)
- **F8 설정**: 질문 주기·시간·요일·채널, 목표 직무
- **F9 마스터 이력서**: 재료 풀(기본 정보·기술 스택·프로젝트·경력·활동·학력·수상), 포함/제외, 문장 편집·순서 변경, 새로 쌓인 재료(코드 분석·경험이 담긴 카드) 담기, 출처·근거 보기, 이력서 미리보기, 버전 저장·비교·되돌리기
- **F10 레포 코드 분석**: 프로젝트에 GitHub 레포 연결 → 코드 분석 → 이력서 항목 후보(근거 파일·줄 포함) → 골라서 마스터 이력서에 담기

### 7.2 확장 (취업/커리어) — **지원 기업 단위**로 준비
기업(+직무)마다 요구하는 역량, 자소서 문항, 면접에서 집중할 내용이 다르므로 역량 맵·자소서·면접 준비는 전역이 아니라 **지원 기업별로 따로** 존재한다. 경험 카드는 공용 자산이고, 지원 기업은 그 경험을 "어떻게 꺼내 쓸지"를 정하는 단위다.

- **E0 지원 기업 관리**: 기업명·직무·마감일·채용공고(JD) 등록, D-day, 준비도. 목록은 상태별 칸반 보드(지원 준비중 → 지원 완료 → 합격 / 불합격)이며 카드를 끌어 옮기면 상태와 칸 안 순서가 바뀐다 (모바일은 길게 눌러 상태 선택)
- **E1 기업별 역량 맵**: JD를 분석해 요구 역량(가중치 ★1~3 + 근거 문장) 추출·수정 → 역량마다 이 기업용 대표 경험 1개 고정, 30초 답변 카드, 준비됨/경험 없음 표시, 요구되지 않는 "내 다른 강점"도 함께 표시
- **E2 기업별 자소서**: 기업의 자소서 문항 목록 → 문항별 숨은 키워드(기업 요구 역량과 겹치면 강조) → 경험 추천·연결 → 개요(도입/상황/행동/결과/직무 연결), 같은 경험 중복 사용 경고
- **E3 기업별 면접 준비**: 이 기업에서 집중할 것(가중치 높은 역량, 자소서 꼬리질문, 약한 역량), 예상 질문 리스트(공통/요구 역량/자소서 꼬리질문/직접 추가) + 경험 연결·답변 포인트·준비 완료 체크, 연습 모드
- **역량 준비 규칙**: 요구 역량은 그 역량 키워드가 붙은 경험 카드가 **하나라도 있으면 준비됨**, 없으면 경험 없음 (중간 단계 없음). 대표 경험은 이 기업용으로 고정한 카드가 있으면 그것, 없으면 그 역량 카드 중 **담긴 경험이 가장 많은 카드**(같으면 최근 수정한 카드)를 AI가 임시로 고른다.
- **준비도** = (준비된 요구 역량 비율 + 경험이 연결된 자소서 문항 비율 + 준비 완료한 면접 질문 비율)의 평균. 자소서 문항이나 면접 질문이 아직 없으면 그 영역은 0%로 계산한다

## 8. 비기능·UX 원칙
1. **빈 화면을 주지 않는다** — 항상 질문이나 다음 행동이 먼저 보인다
2. **한 번에 하나** — 질문은 하나씩, 답변은 짧아도 된다
3. **언제든 멈출 수 있다** — 모든 질문 흐름에 탈출구
4. **쌓이는 게 보인다** — 답변 즉시 카드·담긴 경험·키워드에 반영
5. **원문은 보존** — AI 정리본과 사용자 원문 답변을 함께 보관
