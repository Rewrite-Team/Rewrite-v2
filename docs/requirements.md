# AI 기반 경험관리 서비스 — 요구사항 정리 (v0.3)

> 가칭 **Rewrite** · "문서를 쓰기 전에, 경험부터 발굴한다"

## 1. 한 줄 정의

사용자가 프로젝트마다 **AI와 대화**하거나 **GitHub 레포를 연결**하면, 그 과정·의사결정이 **STAR 경험 카드**로 정리되고 **정해진 역량 카테고리**와 연결되는 경험관리 서비스.

## 2. 문제 정의 (왜 만드는가)

| # | 사용자가 겪는 문제 | 서비스의 대응 |
|---|---|---|
| P1 | 평범한 활동은 "경험"이 아니라고 생각한다 | 알바·스터디·팀과제·해커톤도 모두 하나의 프로젝트로 담는다 |
| P2 | 어떤 경험을 이야기할지 떠올리지 못한다 | 새 채팅은 안내로 시작하고, 한 줄을 적으면 AI가 빈칸을 물어본다 |
| P3 | 경험 속 의미 있는 행동을 집어내기 어렵다 | 꼬리질문으로 상황·과제·행동·결과를 나눠 STAR로 정리 |
| P4 | 경험이 어떤 직무 역량을 보여주는지 모른다 | 12개 역량 카테고리 안에서 골라 연결 |
| P5 | GitHub에 결과물은 남아도 과정은 사라진다 | 코드·커밋·PR을 읽어 STAR 경험 카드로 정리 |

## 3. 타깃 사용자

1. **신입 취업 준비생** (핵심 타깃) 2. **직무 전환 준비생** 3. **주니어 이직 준비생**

## 4. 화면 원칙

1. **한 페이지에 한 가지 일** — 주 영역은 하나. 부가 정보는 접기·모달·하위 화면으로 옮기고, 같은 정보를 두 곳에서 보여 주지 않는다.
2. **한 번에 하나** — 질문은 하나씩, 답변은 짧아도 된다.
3. **결과는 항상 경험 카드** — 대화도 레포 분석도 경험 카드를 새로 만들거나 고치는 것으로 끝난다.

## 5. 개념과 관계

```
프로젝트 (해커톤·팀과제·알바·스터디… 모두 프로젝트, 유형 구분 없음)
 ├─ GitHub 레포 (만들 때 또는 나중에 연결) ── STAR 초안 → 선택 ─┐
 ├─ 대화방 (여러 개) ── 말하면 AI가 알맞은 카드에 바로 채운다 ─┤
 └─ 경험 카드 (STAR·역량·이력서 한 줄·회고, 여러 장) ◀──────────┘ ──▶ 마스터 이력서 · 지원 기업(자소서·면접)
```

| 개념 | 설명 |
|---|---|
| **프로젝트** | 채팅과 경험 카드를 묶는 단위. GitHub 레포로 만들면 레포 이름이 프로젝트 이름이 된다 |
| **대화방** | 프로젝트 안에서 AI와 이야기하는 곳. **한 프로젝트에 여러 개**를 두고, 무엇을 이야기할지는 사용자가 정해 나눈다. 대화방은 카드에 묶이지 않는다. 한 대화방에서 여러 카드를 채울 수 있다. 이름은 사용자가 정하고 카드 제목과 상관없다 |
| **경험 카드** | 에피소드 하나를 STAR로 정리한 것. 반드시 한 프로젝트에 속하고, 보이는 모든 곳에 프로젝트 이름이 붙는다 |

### 5.1 프로젝트와 GitHub
- **새 프로젝트**는 두 가지다: **GitHub에서 가져오기**(레포를 고르면 그 이름으로 생성) / **직접 만들기**.
- 연결되지 않은 프로젝트는 프로젝트 화면에서 **GitHub 연결**을 할 수 있다. 연결을 풀어도 카드는 남는다.
- 연결된 프로젝트에는 **GitHub로 경험 카드 만들기** 버튼이 있다. 코드·커밋·PR을 읽어 STAR 초안을 만들고, 고른 초안이 하나씩 그 프로젝트의 경험 카드가 된다. 이미 만든 카드는 다시 만들지 않는다.
- 같은 흐름을 **AI 채팅** 안에서도 쓴다: 새 프로젝트(GitHub에서 가져오기), GitHub 연결, GitHub에서 찾기 → 초안 고르기 → 카드 만들기(만든 카드는 그 대화방 오른쪽 패널에 바로 보인다).
- 레포를 고를 때 **GitHub 주소 하나**만 넣으면 내 레포·소속 조직·기여한 레포를 모두 불러온다.
- 프로토타입은 공개 GitHub REST API를 쓴다(시간당 60회, 공개 정보만). 예시 계정 `example`은 예시 데이터를 보여 준다. 분석은 규칙 기반 모의 AI다.

### 5.2 경험 카드가 만들어지고 고쳐지는 방법
- **대화방**: 말하면 **AI가 그 말을 담을 카드를 고른다.** 프로젝트의 카드 중 맞는 것이 있으면 그 카드의 알맞은 칸에 바로 담고, 없으면 새 카드를 만든다. 「다른 이야기」라고 분명히 말하면 새 카드로 시작한다. 빈칸은 빈칸으로 보여 주고 AI가 이어서 묻는다.
- **오른쪽 패널**: 그 프로젝트의 카드를 모두 보여 준다. 하나를 고르면 목록의 제자리에서 펼쳐지며(애니메이션) 자세한 내용이 보이고, 다른 카드는 순서 그대로 남아 고를 수 있다. 펼친 카드의 머리를 다시 누르면 접힌다. AI가 카드를 만들거나 고치면 그 카드가 제자리에서 펼쳐지고, 바뀐 칸은 형광펜으로 보인다.
- 카드를 바꾼 AI 답에는 그 카드 이름이 적힌 칩이 붙고, 누르면 패널에서 그 카드를 연다.
- 「제목을 …로 바꿔 줘」 같은 말은 패널에서 고른 카드에 적용한다. 「되돌리기」는 그 대화방의 마지막 변경을 취소한다.
- 입력창 위의 **「카드 바꾸기 전에 묻기」 토글**(계정마다, 기본 꺼짐). 켜면 AI가 카드를 만들거나 고치거나 지우기 전에 바뀔 칸만 앞뒤로 보여 주고 「반영하기」「항상 허용」「거절」을 묻는다. 거절한 말은 카드에 담지 않는다. 허락을 기다리는 사이 카드가 바뀌었으면 반영하지 않는다. 「항상 허용」은 토글을 끈다.
- 대화방을 지워도 카드는 남는다. 카드를 지워도 대화방은 남는다.
- **GitHub**: 5.1의 흐름.
- **직접 만들기**: 프로젝트 화면의 「직접 만들기」에서 제목만 적으면 빈 카드가 생긴다. AI 없이 카드에서 나머지를 쓴다.
- 카드에서 **제목·역량·STAR·이력서 한 줄·회고**를 모두 직접 고칠 수 있다. 대화방에서 말로 채우고 고칠 수도 있다(「결과를 …로 바꿔 줘」). 직접 고친 뒤에는 대화방의 「되돌리기」가 그 전으로 돌리지 않는다.
- 카드의 **대화방에서 채우기**는 그 카드의 프로젝트에 새 대화방을 열고, 패널에서 그 카드를 골라 둔다.

### 5.3 경험 카드 필드
| 필드 | 설명 |
|---|---|
| 프로젝트 | 카드가 속한 프로젝트 (필수) |
| 제목 · 기간 · 역할 · 한 줄 요약 | |
| **STAR** | 상황(S) · 과제(T) · 행동(A) · 결과(R). AI가 모르는 수치는 지어내지 않고 비워 둔다 |
| **역량** | 아래 12개 중 1~3개 |
| **이력서 한 줄** | 이력서에 그대로 들어가는 문장(명사형 종결). AI가 먼저 쓰고 사용자가 고칠 수 있다. 마스터 이력서와 같은 문장을 공유한다 |
| **회고** | 사용자가 필요할 때 직접 쓰는 글. AI가 만들거나 고치지 않는다 |
| 근거 | GitHub 커밋·PR·코드(접어서 보여 준다) |

### 5.4 역량 카테고리 (고정 12개)
문제 해결력 · 분석적 사고 · 창의력 · 기획력 · 커뮤니케이션 · 의사결정 능력 · 리더십 · 추진력 · 실행력 · 도전정신 · 학습능력 · 협업능력

AI는 이 안에서만 고르고, 새 카테고리를 만들지 않는다. 자소서·면접 질문의 핵심 역량도 같은 목록을 쓴다.

### 5.5 휴지통
- 프로젝트·채팅·경험 카드·지원 기업을 지우면 휴지통으로 간다. 30일 동안 복원할 수 있고, 지나면 완전히 지워진다.
- 프로젝트는 안의 채팅·경험 카드와 한 묶음으로 들어간다. 속한 프로젝트가 휴지통에 있는 카드·채팅을 복원하면 프로젝트도 함께 복원한다.
- 지운 직후에는 알림의 **되돌리기**로 바로 되살린다. 완전 삭제와 비우기만 확인을 받는다.

### 5.6 계정
- 회원가입(이름·이메일·비밀번호 8자 이상) · 로그인 · 로그아웃 · 회원 탈퇴(비밀번호 확인, 계정과 데이터 삭제). 예시 계정으로 둘러볼 수 있다.
- 데이터는 계정마다 나뉜다. 프로토타입은 서버가 없어 이 브라우저(localStorage)에만 저장하고, 비밀번호는 PBKDF2 해시만 남긴다. **실제 서비스의 인증으로 쓸 수 없다.**

## 7. 꺼내 쓰기

- **마스터 이력서**: 왼쪽에서 고치면 오른쪽 이력서가 바로 바뀐다. 프로젝트·경력·활동은 **경험 위키의 프로젝트를 가져오고**, 그 안에서 **경험 카드를 골라** 이력서 한 줄을 그대로 싣는다. 학력·수상은 직접 쓴다. 버전 저장/비교/복원, 인쇄·PDF.
- **지원 기업**: 상태 칸반(지원 준비중 → 지원 완료 → 합격 / 불합격). 기업 화면에는 **채용공고 링크**가 항상 보이고, 공고 · 자소서 · 면접 준비 탭이 있다.
- **자소서**: 문항의 핵심 역량에 맞는 경험 카드를 **모두** 보여 주고 하나 이상 고른다. 고른 카드는 프로젝트와 함께 보인다. 고른 뒤 **AI로 자소서 생성**으로 초안을 만들고 직접 다듬는다. AI는 카드에 있는 사실만 쓰고, 모르는 것(지원 이유·배운 점 등)은 `[ ]`로 남긴다.
- **준비도** = 다 쓴 자소서 문항(본문이 있고, `[ ]`가 남지 않고, 글자 수 안)과 준비를 마친 면접 질문의 비율.

## 9. 열린 질문
- 실제 인증(서버·소셜 로그인·비밀번호 재설정)과 GitHub OAuth 범위(비공개 레포·조직), 코드 원문 저장 여부
- GitHub 초안과 이미 대화로 만든 카드가 같은 이야기일 때 합치는 기준
- 지원 기업별로 마스터 이력서에서 골라 낸 '제출용 이력서'를 따로 둘지
